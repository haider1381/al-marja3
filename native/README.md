# Medbrain native preparation

This Capacitor 8 project embeds the site and adds native share/export, haptics, Android back handling, external PDF/browser handling and optional local focus-session notifications. It does **not** load the app through a remote `server.url`. Android and iOS sources are generated by the checked-in script; generated platforms and web outputs are ignored.

```sh
cd native
npm ci
npm run prepare:platforms
npm run android
# On a Mac with Xcode:
npm run ios
```

`npm ci` uses pinned versions and the committed lockfile. `prepare:platforms` builds local web assets, generates both platform projects if absent, configures callbacks, safe local notifications, Medbrain brain icons, disables Android app backup, and installs an Apple privacy manifest. `npm run sync` updates bundled UI/plugins after changes. The source icon is `resources/app-icon-1024.png`.

Provisional app ID: `com.haider1381.medbrain`; confirm its availability in owner developer accounts before signing or altering callback schemes. Native compilation requires Android SDK 36/Java 21 and a supported Mac/Xcode toolchain for iOS. SDK signing, physical-device testing, APK/AAB/IPA packaging and store submission were not done in this environment.

## Login before release

Web Google login is unchanged. Native builds use the local Supabase client in PKCE mode. Native Google login defaults **disabled** in `release-config.json`, preventing Google sign-in inside an embedded WebView or an unconfigured callback; password/reset login is available. Before enabling native Google, add `com.haider1381.medbrain://auth/callback` to Supabase redirect allowlist and verify the same scheme in the native projects. The native adapter launches the system authentication browser and exchanges the callback code using the device's PKCE verifier; callback scheme/host/path/pending time are checked, and cold starts retain only a temporary OAuth-start timestamp.

For iOS with third-party Google login enabled, provision and implement an equivalent Apple-compliant sign-in option (typically Sign in with Apple). The current `appleSignInConfigured` flag is false and no Apple login is falsely advertised. Configuring Sign in with Apple requires owner Apple Developer capability/service identifiers and server-side credentials entered privately in Supabase. Adding the flag alone does not implement the feature. Account deletion must then also revoke Apple tokens as required by Apple's provider documentation; that extension is not part of this Google/password release.

## Privacy and notifications

Focus notifications are requested only after a student checks the explicit notification option and starts a period. The content is generic and carries no lecture, name or medical data. Timing uses wall-clock deadlines; no exact-alarm or background execution permission is requested. OS scheduling/background behavior must be checked on actual devices. Timer state is kept in memory and does not survive full app termination.

Export creates an account-data JSON file only at the student's request, in the native app's private temporary cache, then opens the OS share/save sheet. That explicit export is distinct from PWA worker caching. The app removes its temporary Medbrain export files on account change/sign-out; the operating system may also clear the cache. Copies explicitly saved/shared outside the app remain under the student’s control. Students choose where to save/share their exported data. No contact/location/microphone/camera permissions were added. Existing image-upload behavior uses the device picker and must be device-tested.

The generated Apple privacy manifest declares accessed file-timestamp and user-default reasons for bundled SDKs. Review the archive's aggregated SDK manifests and actual data collection for App Store privacy labels; this file is not a claim of App Store approval or a substitute for review.

## Release gate

`npm run release:check` intentionally fails until owner-reviewed support email, actual-device tests, content rights, privacy declarations and signing are recorded. Do not bypass the gate merely to upload. It also blocks enabling native Google in an iOS release without an equivalent configured Apple-compliant login.

See `../docs/mobile-and-store-readiness.md` for feature validation and outstanding release work.
