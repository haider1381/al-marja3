# المرجع — مكتبة المحاضرات الطبية

موقع عربي RTL مستقل، يحتفظ بواجهة الملف الواحد والبحث والتصفح والقارئ الداخلي والوضع الداكن التلقائي. يستخدم Supabase Auth وSupabase للبيانات، ولا يحتاج Claude.

## حالة الإعداد
تم تجهيز الكود وSQL؛ **لم يتم تطبيق SQL أو التحقق من السياسات الحية**. يجب تطبيق الإعدادات التالية قبل دمج الفرع ونشره. المفتاح الموجود publishable عام؛ لا تضع service_role أو كلمة مرور قاعدة البيانات في الموقع.

## إعداد Supabase
1. افتح المشروع wuvzteosknrzddsaexez. خذ نسخة احتياطية من البيانات، واحفظ تعريف سياسات RLS الحالية قبل التطبيق:
   `select * from pg_policies where schemaname = 'public' and tablename in ('lectures','access_codes');`
2. راجع ثم نفذ [migration](supabase/migrations/202610020001_auth_rls.sql) في SQL Editor. يحتفظ بكل الصفوف والحقول؛ يستبدل سياسات lectures ويلغي وصول المتصفح إلى access_codes. إن فشل أي أمر تتراجع المعاملة كلها.
3. في Authentication فعّل Email/password، وعطّل السماح بالتسجيل العام إن كانت المكتبة بالدعوات فقط. أنشئ المستخدمين من لوحة التحكم بكلمات مرور قوية، مع تأكيد البريد حسب إعدادات المشروع. لا توجد صفحة تسجيل عامة في الموقع.
4. القراءة متاحة لكل حساب مسجل. امنح المحرر صلاحية من SQL Editor فقط، باستخدام UUID من Authentication → Users:
   `insert into private.editors (user_id) values ('USER_UUID') on conflict do nothing;`
   لإلغاء الصلاحية: `delete from private.editors where user_id = 'USER_UUID';`
   لا يُستخدم user_metadata أو الدور المحفوظ في المتصفح لإجازة الكتابة. أعد الدخول لتحديث ظهور الأزرار؛ RLS يطبق الإلغاء على كل طلب كتابة فورًا.
5. إعداد Site URL إلى عنوان الموقع النهائي. لا يعتمد الدخول بكلمة المرور على redirect؛ عند استخدام دعوات أو استعادة كلمات المرور اضبط عناوين redirects وتدفق الاستعادة المناسب أولًا.
6. راجع أي views أو functions قديمة تعرض access_codes أو تكتب lectures بصلاحيات security definer؛ migration يغلق وصول الجدولين المباشر ولا يفحص واجهات مخصصة غير معروفة.

## التحقق بعد التطبيق
استخدم بيانات اختبار منفصلة عن المحاضرات الحقيقية:
- غير المسجل: يجب رفض قراءة lectures وكل العمليات على access_codes.
- حساب قارئ: يقرأ ويبحث ويتصفح ويفتح النصوص والروابط، وتُرفض POST/PATCH/DELETE على lectures حتى لو غيّر الواجهة أو localStorage.
- محرر: يضيف سجل اختبار ويعدله ويحذفه؛ افحص البيانات عبر لوحة Supabase.
- حاول قراءة جميع access_codes بالمفتاح العام، ثم بجلسة القارئ والمحرر: يجب ألا تُكشف أية صفوف.
- أزل المحرر من private.editors وتأكد أن الكتابة التالية تُرفض.
- اختبر إعادة تحميل الصفحة واستعادة الجلسة والخروج وانقطاع الشبكة، وموبايل/آيباد والوضع الداكن.
- تأكد من تحميل كل البيانات عند تجاوز 500 أو 1000 سجل.

## GitHub Pages
بعد تطبيق SQL والتحقق، ادمج فرع التعديل، ثم Settings → Pages → Deploy from a branch → main → /(root).
المستودع خاص؛ توافر Pages للمستودعات الخاصة يعتمد على خطة GitHub، وقد يكون الموقع المنشور عامًا بينما البيانات محمية بتسجيل الدخول وRLS. يمكن استخدام استضافة static أخرى تدعم HTTPS.
لا توجد عملية build. يلزم وصول المتصفح إلى Supabase وCDN لمكتبة supabase-js المثبتة على إصدار 2.57.4 وخطوط Google.
