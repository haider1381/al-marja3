# المرجع — مكتبة المحاضرات الطبية

واجهة عربية RTL قائمة على الموقع الأصلي. الأولوية الآن هي تعبئة مكتبة مشتركة لك ولصديقك، والتصفح والبحث وقراءة المواد والأسئلة. لم يُنفذ نظام اشتراكات الطلاب أو أكوادهم أو تطبيق المتاجر بعد.

## ما تعمل عليه هذه النسخة
- بحث بالاسم والمصدر والموضوع ونوع المادة، مع فلاتر يمكن جمعها.
- تصفح حسب المصدر → التخصص → الموضوع، أو حسب التخصص والموضوع.
- أقسام محاضرات وملخصات وPDF، فيديوهات، أسئلة؛ مع الاحتفاظ بالمواد القديمة من نوع أخرى.
- قارئ نص المحاضرة الحالي، وروابط HTTP(S) للفيديوهات والملفات.
- رفع PDF حتى 25 MB من نموذج الإضافة إلى Storage خاص.
- إنشاء مجموعات حتى 100 سؤال؛ لكل سؤال أربعة خيارات وجواب صحيح وتفسير لكل خيار.
- اختيار الجواب ثم التصحيح وتفسيرات الخيارات، والتنقل بين الأسئلة والنتيجة وإعادة المحاولة.
- إضافة وتعديل وحذف المواد للمحررين، وزر تحديث المكتبة لجلب إضافات صديقك.
- الحفاظ على CSS الأصلي والألوان وRTL والوضع الداكن التلقائي؛ الإضافات تستخدم نفس أسلوب الواجهة.

## حالة التنفيذ
الكود وملفات SQL جاهزة للمراجعة في الفرع feature/library-authoring-mcq. **SQL لم يُطبق، وRLS وStorage لم يُختبرا على Supabase الفعلي، ولم يُنشر الموقع أو يُدمج الفرع.**
الدخول بالبريد وكلمة المرور هنا مخصص لمرحلة إعداد المكتبة وحسابات المحررين. تفاصيل أكواد اشتراك الطلاب مؤجلة، ولا ينبغي فتح قراءة أو كتابة عامة لتجاوز الإعداد.

## الإعداد مرة واحدة
1. افتح Supabase، المشروع wuvzteosknrzddsaexez.
2. خذ نسخة من بيانات lectures وaccess_codes واحفظ السياسات الحالية:
   `select * from pg_policies where (schemaname='public' and tablename in ('lectures','access_codes')) or (schemaname='storage' and tablename='objects');`
3. راجع ونفذ بالترتيب في SQL Editor:
   - [صلاحيات المحررين](supabase/migrations/202610020001_auth_rls.sql)
   - [الأسئلة وملفات PDF](supabase/migrations/202610020002_library_content.sql)
   الملف الأول يستبدل سياسات lectures ويغلق access_codes دون حذف الصفوف. الثاني يضيف file_path وquestions ويُنشئ bucket خاصًا lecture-files، مع قيود تخزين. كل ملف داخل معاملة، فلا يستمر تطبيقه جزئيًا إذا فشل.
   إذا كان bucket lecture-files موجودًا بإعدادات مختلفة، يتوقف SQL لتراجعه أولًا؛ لا تغيّر خصوصيته دون مراجعة الملفات.
4. فعّل Email/password في Authentication. عطّل التسجيل العام إن أردت الحسابات بالدعوات فقط.
5. أنشئ حسابك وحساب صديقك من Authentication → Users، وسجل UUID لكل منهما. لا تحفظ كلمات المرور في GitHub. امنحهما صلاحية:
   `insert into private.editors (user_id) values ('YOUR_UUID'), ('FRIEND_UUID') on conflict do nothing;`
   إلغاء الصلاحية:
   `delete from private.editors where user_id = 'USER_UUID';`
6. شغّل الموقع عبر HTTPS أو localhost، وادخل بالحساب. المفتاح الموجود publishable فقط؛ لا تحتاج service_role أو database password في الواجهة.

إذا لم يكن جدول lectures موجودًا أو لم تطابق حقوله المخطط المعروف، توقف وراجع المخطط بدل استبداله. هذه migrations تتعمد عدم إعادة إنشاء الجدول أو تغيير IDs والبيانات الحالية.

## إضافة المواد من الواجهة
1. اضغط إضافة مادة.
2. اكتب الاسم والمصدر واختر التخصص والموضوع ونوع المادة.
3. للمحاضرة: الصق النص؛ يمكن إضافة PDF إلى نفس المادة.
4. لملف PDF: اختر الملف من جهازك أو أبق رابط الملف الخارجي الموجود.
5. للفيديو: ضع رابط الفيديو.
6. للأسئلة: اختر أسئلة ثم إضافة سؤال. اكتب السؤال والخيارات، حدد الإجابة الصحيحة واكتب تفسيرًا لكل خيار. كرر ثم احفظ.
7. تظهر الإضافة في المكتبة بعد الحفظ. المستخدمون الآخرون يحصلون عليها عند فتح الموقع أو الضغط على تحديث المكتبة؛ لا يوجد اشتراك realtime حاليًا.

لا تحتاج إلى GitHub لإضافة المحتوى. النصوص والأسئلة في قاعدة البيانات والملفات في Supabase Storage، لذا لا تحتاج تحديث التطبيق لإضافة مادة. تحتاج اتصالًا بالإنترنت؛ التخزين دون إنترنت والتنزيل المحلي لم يُنفذا بعد.

## PDF وإدارة الملفات
الروابط الداخلية مؤقتة لمدة خمس دقائق، والـbucket خاص. يفتح الزر PDF في نافذة أو صفحة مناسبة؛ يحدد المتصفح/الجهاز عرضه أو تنزيله أو فتحه بقارئ خارجي، ولا يمكن للموقع إجبار كل الأجهزة على قارئ معين.
استبدال PDF أو إزالة ارتباطه أو حذف المادة لا يحذف الملف القديم من Storage تلقائيًا. نحافظ عليه لتجنب فقدان الملفات أو حذف ملف قد تستخدمه مادة أخرى. يجب مراجعة الملفات غير المرتبطة وحذفها من لوحة Supabase بعد التحقق.
عند فشل الاتصال أثناء الحفظ قد يكون الطلب قد وصل للخادم: تحقق بتحديث المكتبة قبل تكرار الإضافة، خصوصًا إذا ظهرت رسالة أن الملف رُفع.

## اختبار قبل الاستخدام
استخدم مواد اختبار منفصلة:
- المحرر: أنشئ نصًا وPDF وفيديو ومجموعة سؤالين، عدّلها واحذف مواد الاختبار.
- حساب قارئ غير موجود في private.editors: اختبر التصفح والبحث والفلاتر والقارئ والاختبار وPDF، وتأكد من رفض INSERT/UPDATE/DELETE حتى مع تعديل المتصفح.
- غير المسجل: لا يقرأ lectures أو الملفات الخاصة، ولا يرفع PDF.
- جميع أدوار المتصفح: لا تستطيع قراءة access_codes.
- افحص سياسات storage.objects: القيود restrictive الجديدة تحمي lecture-files حتى مع وجود سياسات permissive قديمة. راجع أي RPC أو views قديمة بصلاحيات مرتفعة، وأي buckets عامة تحتوي الملفات سابقًا، إذ لا يستطيع migration اكتشاف واجهات غير معروفة.
- حاول رفع ملف غير PDF أو أكبر من 25 MB.
- اختبر كل اختيار صحيح وخاطئ والنتيجة وإعادة المحاولة والتنقل.
- اختبر تغير جلسة الدخول، انقطاع الإنترنت أثناء الحفظ، والحفاظ على المدخلات عند الرفض.
- اختبر الهاتف والآيباد وRTL والوضع الداكن، وفتح الملفات فعليًا.
- الأسئلة تعليمية، وليست امتحانًا سريًا: الإجابات والتفسيرات تصل للمتصفح لتقديم التغذية الراجعة.
- تعديلات المحررين على المادة نفسها تتبع آخر حفظ؛ نسّقا العمل لتجنب استبدال تعديل أحدكما.

## فحوص الكود
من جذر المستودع مع Node:
```sh
node tests/library.test.cjs
node tests/authoring.test.cjs
```
بلا dependencies إضافية وبلا اتصال أو كتابة في Supabase. تم تشغيل المنطق المكافئ بمحاكاة في بيئة JavaScript المتاحة: 25 فحصًا للبحث والتصنيفات والتحقق من الأسئلة وPDF والتحويل والهروب من HTML، ومحاكاة رفع/حفظ PDF وفشل التعديل مع بقاء المدخلات واستعادة الأزرار.
لم تتوفر أدوات Node أو متصفح أو SQL في الجلسة؛ لذلك أوامر Node أعلاه لم تُشغل مباشرة، والفحوص لا تثبت صحة سياسات SQL أو واجهة الهاتف.

## التشغيل والنشر
لا يوجد build؛ index.html يحتوي الواجهة والمنطق. يلزم وصول إلى Supabase وCDN لمكتبة supabase-js وخطوط Google.
بعد تطبيق SQL والفحص، ادمج فرع التعديل ثم Settings → Pages → Deploy from a branch → main → /(root). توافر GitHub Pages لمستودع خاص يعتمد على خطة الحساب؛ يمكن استخدام استضافة static HTTPS أخرى.
النشر في Google Play وApp Store وتحويل الموقع إلى تطبيق سيأتي بعد اختبار هذه المرحلة، ويحتاج إعداد مشروع تطبيق وحسابات المطور ومراجعة متطلبات المتاجر.
